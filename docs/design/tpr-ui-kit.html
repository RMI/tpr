Transition Pathways Repository · UI reference

Pathways UI Kit

Every color, type size, and reusable interface component currently shipping in the TPR front end, taken from src/index.css and src/components/. Each entry carries the real Tailwind class names and CSS custom properties, so a Figma file built from this stays traceable back to the code that renders it. Colors and class tags are exact; the previews are hand-built and can drift from the code in small ways. Where a preview and its tags disagree, the tags win.

Component previews sit on a fixed light stage regardless of the reading theme below, so colors always read exactly as they do in the shipped app.

Updated for v2. This edition includes the redesign in RMI/tpr#937 (epic/v2): a new rose color family, a sector-segment badge, selectable badges, tabbed detail pages, scope ribbons, data tables, and grouped panels. Entries marked v2 come from that pull request, which was still open (not merged) at the time of this snapshot — treat them as the target design, not yet live.

Typography

No brand typeface is defined anywhere in the codebase — no @font-face, no webfont link. Every screen renders on the browser's own system font. That's a real gap, not a hidden setting: worth a deliberate decision, not an assumption.

Current stack (unset by design intent): ui-sans-serif, system-ui, sans-serif, "Apple Color Emoji", "Segoe UI Emoji", "Segoe UI Symbol", "Noto Color Emoji" — Tailwind's default, inherited automatically because tailwind.config.ts never overrides fontFamily.

Using this in Figma

Two ways in, pick based on what you need first.

Option A — colors & type as Figma variables

  1. Install the Tokens Studio plugin (free) in Figma.
  2. Import tpr-design-tokens.json (in the same folder as this page) as a token set. The block below is a short, valid excerpt showing the format.
  3. Use Tokens Studio's "Create Styles/Variables" action to turn every entry into a real Figma color variable and text style, named identically to the CSS tags above. 
{
  "color": {
    "bluespruce": { "value": "#003b63", "type": "color" },
    "energy": { "value": "#45cfcc", "type": "color" },
    "energy-700": { "value": "#2ab5b2", "type": "color" },
    "rmigray-800": { "value": "#231f20", "type": "color" }
  },
  "fontSize": {
    "sm": { "value": "14px", "type": "fontSizes" },
    "base": { "value": "16px", "type": "fontSizes" }
  },
  "borderRadius": {
    "md": { "value": "6px", "type": "borderRadius" },
    "full": { "value": "9999px", "type": "borderRadius" }
  }
}

The complete file — all 60+ colors, the type scale, weights, radius, and shadow tokens — is tpr-design-tokens.json, in the same folder as this page. Its colors are generated from src/index.css automatically, so they always match the app.

Option B — component shapes as editable Figma layers

  1. Install the html.to.design plugin in Figma.
  2. Download this file (tpr-ui-kit.html) from the repository, then drop it into the plugin's File tab.
  3. It converts the rendered badges, cards, buttons, and dropdowns straight into native Figma frames, text, and fills — a real starting point to refine rather than a picture to trace.
Keeping this from going stale: the colors in the token file update automatically, but this page is maintained by hand. When a component changes, update this page in the same pull request, then refresh the Figma copy from it rather than editing Figma directly — otherwise the two will quietly drift apart. See docs/design/README.md for what is automatic and what is manual.
